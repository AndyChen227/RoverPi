# Devlog — 2026-08-10

## English

### Milestone

RoverPi progressed from a single verified motor-driver channel to verified four-wheel forward, backward, and stop control from both timed Python tests and a PS5 DualSense controller.

### Work completed in order

1. Reconnected the DualSense and diagnosed why the previously used `event11` path disappeared.
2. Confirmed that Linux `/dev/input/eventX` numbers are assigned dynamically after reconnects and reboots.
3. Reconciled two different left-stick scales:
   - `jstest` Y: forward `-32767`, center `0`, backward `+32767`.
   - Python `evdev ABS_Y`: forward approximately `0`, center `128`, backward approximately `255`.
4. Used the DualSense to command the left-side Channel 1 motors forward, stop, and backward.
5. Confirmed the actual chassis-relative Channel 1 polarity; rover-forward is `INA1 off / INB1 on`.
6. Added and tested Channel 2 on BCM GPIO13/5/6.
7. Verified right-side forward, stop, and backward; rover-forward is `INA2 on / INB2 off`.
8. Ran all four wheels through forward → stop → backward → stop at 30% PWM.
9. Used DualSense `ABS_Y` to control all four wheels forward, backward, and stop.
10. Implemented `ABS_X` differential spin-turn functions for left and right.

### Verified GPIO and polarity

| Side | PWM | A | B | Forward | Backward |
|---|---:|---:|---:|---|---|
| Left / Channel 1 | BCM12 | BCM23 | BCM24 | A off, B on | A on, B off |
| Right / Channel 2 | BCM13 | BCM5 | BCM6 | A on, B off | A off, B on |

### Physically verified today

- Channel 1: forward, backward, and stop.
- Channel 2: forward, backward, and stop.
- Four-wheel timed sequence: forward, stop, backward, stop.
- DualSense-controlled four-wheel forward, backward, and stop.
- Low-speed operation at 30% PWM with short test intervals.

### Implemented but not physically verified

- Spin left: left side backward, right side forward.
- Spin right: left side forward, right side backward.
- Horizontal stick commands have priority in the current discrete test controller.

Turning must not be described as complete until it passes a wheels-lifted physical test and a controlled ground test.

### Debugging lessons

**Dynamic event paths:** `event11` identified the main controller during one session only. Future scripts need device discovery rather than a permanent event number.

**Different API scales:** `jstest` and Python `evdev` exposed different numeric ranges and signs. Movement thresholds must match the API that the code actually reads.

### Next steps

1. Physically verify left and right turns with all wheels lifted.
2. Add reliable DualSense discovery by device identity.
3. Add a controller-disconnect/input-timeout stop.
4. Validate standalone operation without an active SSH session.
5. Extract stable motor-control logic into `src/` only after these safety behaviors are dependable.

## 中文

### 今日里程碑

RoverPi 从“只验证一个电机驱动通道”推进到了“两路驱动、四轮前进/后退/停止均已实测”，并且已由 PS5 DualSense 左摇杆实际控制四轮前进、后退和停止。

### 按顺序完成的工作

1. 重新连接 DualSense，并排查之前的 `event11` 为什么消失。
2. 确认 `/dev/input/eventX` 会在重连或重启后动态变化。
3. 区分两套摇杆数值：`jstest` 前推为 `-32767`、居中为 `0`、后拉为 `+32767`；Python `evdev ABS_Y` 前推约为 `0`、居中约为 `128`、后拉约为 `255`。
4. 用 DualSense 控制左侧 Channel 1 前进、停止和后退。
5. 确认左侧实际前进极性为 `INA1 off / INB1 on`。
6. 接入并测试 Channel 2：PWM=BCM13、A=BCM5、B=BCM6。
7. 验证右侧前进、停止和后退，实际前进极性为 `INA2 on / INB2 off`。
8. 让四轮以 30% PWM 完成前进 → 停止 → 后退 → 停止。
9. 用 DualSense `ABS_Y` 实际控制四轮前进、后退和停止。
10. 加入 `ABS_X` 左右原地差速转向函数。

### 已实测

- 左侧 Channel 1 前进、后退、停止。
- 右侧 Channel 2 前进、后退、停止。
- 四轮定时前进、停止、后退、停止。
- DualSense 控制四轮前进、后退、停止。

### 只实现、尚未实测

- 左转：左侧后退，右侧前进。
- 右转：左侧前进，右侧后退。
- 当前离散控制中，X 轴转向命令优先于 Y 轴。

在完成架空测试和受控地面测试之前，不能把左右转写成已完成能力。

### 调试经验

- `event11` 不是永久设备名；重连后必须重新查找，后续需要自动发现设备。
- `jstest` 与 `evdev` 虽然读取同一个摇杆，但数值范围和方向表示不同；阈值必须与实际使用的 API 匹配。

### 下一步

先架空实测左右转，再加入手柄自动发现、断线/输入超时安全停止以及无 SSH 独立运行。安全行为稳定后，再把验证过的控制逻辑提取到正式 `src/` 模块。
